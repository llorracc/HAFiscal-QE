## 1. Goal

Produce three consolidated reference artifacts that describe cross-mode behavior of the HAFiscal reproduction pipeline and the provenance of paper outputs:

1. A single factual timing table covering every documented invocation mode.
2. A mode-validity matrix describing which modes produce which output classes.
3. A documentation-only artifact map linking paper-facing figures and tables to their generator scripts and required modes.

These complement the mechanical text-fix work in Part 1. Together they make the documented reproduction path match the actual code path, especially for:

```bash
./reproduce.sh --comp full
```

This split exists because the three artifacts are synthesis-heavy: each one consumes evidence about every mode and every code path, and each benefits from having Part 1's corrected reproduction-path text already in place. Running Part 1 first means this plan's three artifacts can reference accurate paths and corrected reproduction-path descriptions rather than re-deriving them.

The three artifacts are mutually reinforcing — the artifact map cites which mode each paper output requires (linking it to the mode-validity matrix), and the mode-validity matrix can cite the timing table to show how long each "valid" mode actually takes. Producing them in one plan lets the agent maintain consistency across the three.

## 2. Agent Can Do This Independently

These tasks are factual, local to the repository, and safe for the agent to execute end-to-end.

### 2.1 Normalize factual timing presentation

Create one factual timing table based on current code comments, shell help, and benchmark docs. This table should clearly distinguish cold full runs, partial/variant runs, and fast validation modes.

Include:

- `--docs`
- `--data`
- `--comp min`
- `--comp full`
- `--comp max`
- `--comp full --tm-only`
- `--comp full --mc-only`
- `--comp TM-and-MC`

The agent can remove internally inconsistent duplicate timing claims when the replacement table preserves the documented uncertainty and cites where estimates come from.

Validation:

- Check that no remaining README section says default publication `--comp full` is both "4-5 days" and "2-3 hours" without explaining the condition difference.

Estimated agent time: 0.5-1.5 days.
Estimated user time: optional review only.

### 2.2 Add a mode-validity matrix

Add a factual table explaining which reproduction modes can generate which output classes:

- aggregate multipliers and IRFs;
- per-agent welfare tables;
- Lorenz or wealth-distribution outputs;
- HANK/SAM outputs;
- splurge-zero robustness.

This can be derived from existing script comments and output gates, especially the TM-only skip of per-agent welfare outputs.

Validation:

- Confirm every claim is supported by an entry point or code comment.

Estimated agent time: 1-2 days.
Estimated user time: optional review only.

### 2.3 Draft a documentation-only artifact map

Create or update a markdown artifact map that links paper-facing figures and tables to:

- generated output path;
- generator script or function;
- required reproduction step;
- valid reproduction modes (referencing the matrix in 2.2);
- known caveats.

This task is documentation-only. It should not create a machine-readable registry or change generation code.

Validation:

- Check every listed generator path exists.
- Check every listed artifact path exists or is documented as generated by a full run.
- Check that the "valid reproduction modes" column for each artifact is consistent with the mode-validity matrix in 2.2.

Estimated agent time: 1-2 days.
Estimated user time: optional review only.

## 3. Deliverables
